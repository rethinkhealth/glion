---
"@glion/mllp": minor
---

Decode inbound payloads in the runtime-agnostic core and route decode/parse failures to the error handler instead of bypassing the server.

- `Mllp.handle(payload, connection)` now takes the de-framed payload **bytes** (not pre-decoded text). `createContext` decodes (UTF-8) and parses in the runtime-agnostic core, so every transport adapter behaves identically and the Node `serve.ts` adapter just forwards the payload.
- A non-UTF-8 or unparseable payload no longer throws out of band. `createContext` is total — a decode or parser failure yields an empty `Root` recorded on `ctx.error`. `handle()` then surfaces that failure as the **innermost step of the middleware chain** (the same place a route handler runs), so a wrapping middleware — e.g. `@glion/mllp-ack`'s `ackMiddleware` — catches it and builds a NAK, exactly like a thrown handler error. If nothing in the chain handles it, it propagates to the single top-level catch (`#handleError` → the app's `onError`, else re-thrown), mirroring Hono's `try { compose } catch { #handleError }`. A non-UTF-8 frame surfaces as a `MllpServerError` (`code: INCOMPATIBLE_CHARSET`) with the codec's `CharsetError` on `cause` — unchanged from #659/#660, now produced by the core and visible to in-chain middleware.
- **Default error floor.** Every errored message now gets a reply. When neither an ack middleware nor `app.onError` produces a response, the core returns a minimal `MSA|AE` NAK (the HTTP-500 equivalent), echoing the control id when the message was readable — instead of going silent. It is deliberately minimal; `@glion/mllp-ack` (rich, fully-echoed NAKs) or `app.onError` replaces it.
- **Breaking — `serve()`'s `onError` is now transport/lifecycle only.** Semantic errors (handler/middleware throws, decode/parse failures) become a NAK inside the core and no longer reach `serve({ onError })`; observe them with a logger middleware or `app.onError`. `serve.onError` still fires when an error _escapes_ the core: a throwing `onConnect`/`onDisconnect`/`app.onError`, or a missing parser (`NO_PARSER`).
- **Breaking:** `Context.req.bytes` is removed (nothing read it). `ctx.req.raw` is the decoded text (`""` when the payload is not UTF-8), and the new `ctx.error` records the decode/parse failure. Direct `handle()` callers must pass the payload bytes and drop the leading text argument.

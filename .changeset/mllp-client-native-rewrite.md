Rebuild the client as a plain TypeScript core — one connection, single-flight, a pull-based wire.

`MllpClient` is now a thin class over a per-connection wire: the read loop feeds decoded frames into a per-connection inbox, and each send takes its ACK from that inbox under its own deadline. Whichever terminal event comes first — drop, decoder error, write failure, frame flood, or `close()` — latches the connection's one failure, and everything else observes it. Connection-scoped state resets by construction each time the client connects.

**API changes vs 0.17.x** (breaking; the package is 0.x):

- **`send(string | Root)` — the AST is the wire currency.** Every input is parsed to a tree and re-serialized to canonical HL7v2 (an _originating / cleaning_ client, not a byte-exact relay); the same parse yields the MSH-10 correlation ID. `Uint8Array` input is dropped, and `MllpClientResponse.raw` is a `string` (decoded ACK text). Cleaning is syntactic only: line endings normalize to CR and trailing empty fields/segments are trimmed; escapes, Z-segments, repetitions, and components round-trip verbatim.
- **`connect()` is idempotent.** While `connecting` it returns the same in-flight attempt (one connection attempt per instance; every caller sees its outcome, including `CONNECT_ABORTED` when `close()` interrupts), and when already `connected` it resolves immediately. `ALREADY_CONNECTED` is removed — concurrent ensure-connected callers no longer need to catch anything.
- **The outbound boundary is a module.** `send()`'s parse → serialize → encode → frame → correlate chain lives in a named boundary (`prepareOutbound`, the outbound twin of the ACK reader) instead of five inline lines, with the parse function injected internally on both directions. Deliberately not configurable yet: the decided extension model is client-owned `messageProcessor` / `ackProcessor` pipelines that accept _plugins_ (never whole processors, so the compiler is right by construction), arriving with the ACK-pipeline work.
- **A send timeout is connection-terminal.** A timed-out send rejects with `SEND_TIMEOUT` and the client closes the connection — after a timeout, a late acknowledgment could never be matched safely, and keeping the wire would let one transient remote slowdown permanently desynchronize correlation. Resend on a new client, only when safe to repeat.
- **Single-flight.** The FIFO send queue and `client.queueDepth` are removed; a concurrent `send()` rejects with the new `ALREADY_SENDING` code. `connect()` takes no arguments and `MllpSendOptions` is `{ timeoutMs }` only — the cancellation primitives are the per-send `timeoutMs` (the whole-exchange deadline: it covers the frame write AND the ACK wait, so a remote system that stops reading cannot park a send forever) and `close()`, which rejects an in-flight send with `CLOSED`. A transparent FIFO queue returns in a later version.
- **One code for an unusable reply: `INVALID_RESPONSE` — and it is connection-terminal.** Replaces `PARSE_FAILED`, `UNKNOWN_ACK_CODE`, and `CORRELATION_MISMATCH` — undecodable bytes (charset error on `cause`), missing or non-standard MSA-1, and an MSA-2 that doesn't match the request's MSH-10 are all the same caller outcome; the specific reason is in `message`. The client closes the connection on any of them, for the same reason a timeout closes it: a stray or unmatched frame consumed as a later send's acknowledgment would desynchronize every send after it. A NAK still throws an `@glion/ack` `AckException`, unchanged — the remote system answered properly, so the connection survives.
- **`MllpClientState` is `idle | connecting | connected | closed`** (was six phases). `ready`/`sending` collapse to `connected`; `closing` collapses to `closed`. `client.connected` is unchanged.
- **The wire is glue-proof.** The connection reads through `@glion/mllp-codec`'s `unframe()` pipeline. A send timeout no longer resets a partially received frame: the timeout drops the connection, so a stalled partial that later completes lands on a dead wire instead of desynchronizing the next send, and a new frame starting inside an unterminated one drops the connection with a framing error.
- **MSH-10 is required.** HL7v2 mandates the control ID, and without it the acknowledgment cannot be correlated — `send()` now rejects a message with no (or an empty) MSH-10 with the new `INVALID_MESSAGE` code, before anything is written to the wire. (A remote system that omits MSA-2 in its _response_ is still tolerated.) `INVALID_MESSAGE` also covers a serialized message carrying a reserved VT/FS byte — the `@glion/mllp-codec` `MllpCodecError` no longer escapes `send()`; it rides on `cause`.
- **A closed client explains itself.** After a remote drop, a failed connect, or a connect timeout, later `connect()` / `send()` calls reject with `CLOSED` carrying the original failure on `cause` — distinguishable from an owner `close()`, which carries none.
- **An ACK racing the remote system's own close is not lost.** A one-shot remote that writes the acknowledgment and closes the connection in the same instant resolves the in-flight send with that ACK; drop detection defers one macrotask so in-flight deliveries settle first.
- **Smaller error/response surface.** Every client failure is one `MllpClientError` with `code` / `message` / `cause`; `MllpClientErrorDetails`, `MllpDropReason`, and the `SEND_ABORTED` code are removed (there is no per-send cancellation signal — `SEND_ABORTED` had nothing left to mean; `close()` rejects an in-flight send with `CLOSED`). `MllpClientResponse` drops `requestControlId` (you already know the id you sent). NAKs are thrown as `@glion/ack`'s exception classes, mapped from MSA-1 by an exhaustive switch.

Migration:

- Pass a `string` or `Root` to `send()`; if you hold wire bytes, decode them at your I/O boundary (where charset / MSH-18 knowledge lives) and pass the `string`.
- Replace `PARSE_FAILED` / `UNKNOWN_ACK_CODE` / `CORRELATION_MISMATCH` branches with `INVALID_RESPONSE` (inspect `message`/`cause` to distinguish).
- Serialize concurrent sends yourself (or catch `ALREADY_SENDING`) until the queue returns; replace any `queueDepth` polling.
- Replace `ready`/`sending`/`closing` state checks with `connected`/`closed` (or `client.connected`).
- Ensure every outbound message carries an MSH-10 control ID (or catch `INVALID_MESSAGE`).

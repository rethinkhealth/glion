# @glion/mllp-client — architecture: a single-owner mailbox actor

## 0. Thesis

Every one of the 20 review threads on #669 condemns one disease: five independent async contexts — the connect attempt (`client.ts` `#establish`), the send caller, the read loop (`connection.ts` `runReadLoop`), the closed-watcher (`watchForDrop`), and the deadline timers — all mutate shared lifecycle state and must defend against each other, via an abortReason side channel (client.ts `#establish` catch, threads :112/:219/:249), a hand-rolled once-latch (`inbox.failure`, connection.ts `dropConnection`), a macrotask-ordering prayer (`setTimeout(resolve, 0)` in `watchForDrop`, connection.ts:156-166, F7), captured settlers (the `PendingAck` slot, inbox.ts:54 — "pendingTake" in your thread :128 — threads :42/:128), and a terminality allowlist (the SEND_TIMEOUT/INVALID_RESPONSE check in `exchange`'s catch, connection.ts:268, F6).

The rewrite replaces all of them with one owner. A mailbox of typed messages — three commands (`connect`/`send`/`close`, each carrying a reply Deferred) and seven facts (`wireOpen`/`wireOpenFailed`/`connectDeadline`/`frame`/`eof`/`writeFailed`/`sendDeadline`) — is drained by a synchronous run-to-completion dispatcher. `handle(msg)` is the only function that reads or writes state; it is non-async and non-throwing by construction; every async effect reports back as a message. Races become mailbox orderings, and each ordering is a named cell in a [phase x message] matrix a reviewer can enumerate — the structural answer to thread :340 ("Is this robust?? Any risk of concurrency??") in one checkable sentence: there is exactly one mutator, and it never yields mid-decision.

## 3. State model

State is one discriminated union in one closure variable; only `handle()` writes it; the public `state` getter reads `state.phase` synchronously (single writer, safe). Variants carry the data that is only meaningful in that phase, so the current five parallel nullable fields (`#phase`, `#connection`, `#connecting`, `#connectController`, `#closedReason` — client.ts:119-131) and their prose invariants collapse into compiler-checked structure. "connecting with no attempt to join" (the client.ts:206 `connect()` invariant fallback) and "connected with no live connection" (the client.ts:336 `send()` invariant throw) become unrepresentable — both apologetic error strings are deleted, which also answers thread :291.

```ts
type State =
  | { phase: "idle" }
  | {
      phase: "connecting";
      waiters: Deferred<void>[];
      abort: AbortController;
      timer: Timer;
    }
  | {
      phase: "connected";
      wire: Wire;
      pending: Pending | null;
      stash: Uint8Array[];
    }
  | {
      phase: "closed";
      reason: MllpClientError | null;
      teardown: Promise<void>;
    };

interface Pending {
  reply: Deferred<MllpClientResponse>;
  controlId: string;
  timer: Timer;
  sentAt: number;
}
```

Messages: commands `connect { reply }` / `send { reply, input, timeoutMs }` / `close { reply }`; facts `wireOpen { wire }` / `wireOpenFailed { error }` / `connectDeadline` / `frame { bytes, at, wallClock }` / `eof { error? }` / `writeFailed { error }` / `sendDeadline { pending }`. Facts are stamped with time at post (`at: performance.now()`, `wallClock: new Date()`) so `handle()` never reads a clock — a Loom graft that makes every matrix test synchronous. `sendDeadline` carries the `Pending` identity so a timer that fired before its `clearTimeout` landed is provably stale.

## 4. Concurrency model

Races are impossible by construction via three rules, none of which is a guard:

1. **One mutator.** `handle()` is the only reader/writer of `state`; it is synchronous (its non-async `void` signature makes an accidental `await` a type error, not a convention). The current code's safety argument is a comment about await-point interleaving (the `#inFlight` JSDoc, client.ts:122-128); the new argument is the execution model.
2. **Run-to-completion.** `post(msg)` pushes onto a queue; a `draining` latch drains it FIFO; a message posted during handling is processed after the current one, never interleaved. The drain wraps in `try/finally` releasing the latch — a handler throw (a contract violation, since codecs are total) propagates loudly to the poster and never wedges the mailbox. This is XState v5's macrostep semantics in ~15 dependency-free lines.
3. **Stateless effects.** Everything async — `openWire`, `wire.write`, the read pump, `duplex.close()`, both timers — never touches state; its only output is a later `post(fact)`.

Consequences, each an enumerable ordering with a named test: close-vs-connect-resolved → the loser `wireOpen` lands in `closed` and the orphan wire is disposed there (dissolves thread :254); deadline-vs-frame → whichever message is handled first settles the pending, the other is an identity-checked stale; drop-vs-close → the first transition to `closed` wins, the second joins the stored teardown; `await send(); send()` → the resolve continuation runs a microtask after `pending` was cleared inside the same synchronous handler, so no false ALREADY_SENDING (baseline §3.2's release-ordering pin, verified in the doc's checklist item 2 — landed as an explicit regression test BEFORE the cutover commit, per the XState judge's graft); connect∥connect → the second command lands in `connecting` and pushes its reply onto `waiters` (no memoized promise to desynchronize — the client.ts `#connecting` juggling and its :206 invariant fallback are gone).

Calibrated bounds: the mailbox is structurally unbounded but each producer holds O(1) outstanding — the pump posts at most one `frame` per awaited `read()`, and the 16-frame stash cap closes the connection before buffering grows. External posts each trigger their own synchronous drain, so the queue holds >1 message only in narrow cases (a stash re-post during `send` handling; a connector abort listener posting synchronously) — the honest §1 defense is that ~90% of the safety comes from "one synchronous decision function, effects report facts", and the ~15-line queue is what turns the remaining reentrancy cases from convention into structure.

## 5. Cancellation and deadlines

One scheme: deadlines are timers that post messages; the actor is the only decider; exactly one `AbortController` exists in the whole package.

- **Connect**: entering `connecting` arms `setTimeout(connectTimeoutMs)` posting `connectDeadline` and creates the AbortController whose only job is the WHATWG-specified one — cancelling the in-flight connector attempt. The handler for `connectDeadline` (or `close`) rejects waiters and transitions FIRST, then aborts; the adapter's eventual rejection posts `wireOpenFailed` into `closed` and is a straggler cell. Nobody ever reads `signal.reason` to route an error — the routing decision was made when the message was handled. This deletes the abortReason plumbing (client.ts `#establish` catch, :267-282) root and branch (threads :112/:219/:249).
- **Send**: arming a `Pending` arms `setTimeout(timeoutMs)` posting `sendDeadline{pending}`. No AbortController, no signal listeners, no `Promise.race` against the write: a write parked on a peer that stopped reading is bounded by the deadline message — `fail()` closes the wire, the parked write settles against the closing stream, and its `writeFailed` lands in `closed` as a straggler cell. The entire `writeFramed` dual-detached-catch apparatus (connection.ts:179-231) collapses to `writer.write(framed).catch((e) => post(writeFailed(e)))` inside wire.ts.
- **F1 (CONFIRMED)**: `assertTimeoutMs(name, ms)` requires `Number.isFinite(ms) && ms > 0 && ms <= MAX_TIMEOUT_MS` (2^31−1, the setTimeout ceiling, a named constant) and throws `RangeError` naming the option and the received value; applied to `connectTimeoutMs`/`sendTimeoutMs` in the constructor and `opts.timeoutMs` in `send()`, synchronously, before any state change. `RangeError`, not a new `MllpErrorCode`: option misuse is a programmer error and the platform convention (fetch throws TypeError; Node's `net.connect` throws RangeError on a bad port) — the shipped 10-code taxonomy stays reserved for runtime wire/lifecycle failures per ADR 0018. `maxBufferedBytes` gets the same positive-integer check.
- **Timer unref policy** (unified, per the refutation): the connect and send deadline timers stay ref'd — an in-flight operation legitimately holds the event loop (parity with today); the ONLY unref'd timer is the Node adapter's post-close grace timer, which runs after the client is done.
- **Answer to thread :234**: `AbortController`/`AbortSignal` are WHATWG standards implemented in Node ≥15 (this repo's floor is Node ≥20), Deno, Bun, Workers, and browsers — fully runtime-agnostic — and the design shrinks usage to the single seam where a standard signal is exactly right: the public `MllpConnector` contract.
- **No caller `AbortSignal` on `send()`** — unchanged public stance; a send is bounded by its deadline and by `close()`. The seam is ready (a signal listener would post a message) at zero cost today.

## 6. Error model

ADR 0018 preserved intact: two buckets caught separately (`MllpClientError` branched on the shipped 10 codes vs the `@glion/ack` `AckException` family), throw-on-NAK, `cause` always set, `MllpClientResponse` as the happy path only.

**Terminality by construction (F6, inverted).** `fail(error)` is the ONLY code path that concludes a send with an `MllpClientError` after the wire was touched, and its body unconditionally transitions to `closed` and starts `wire.close()` — no code path can reject a send with a wire-layer client error and leave the connection up, because no such path exists. The `frame` handler switches on the codec's exhaustive `AckOutcome`: `accepted` and `rejected` (NAK — the peer answered properly; ADR 0018's opposite-retry-semantics rationale) are the only two arms that keep `connected`; `invalid` rejects the pending with `INVALID_RESPONSE` and funnels to `fail()`. Pre-wire errors (`INVALID_MESSAGE`, `NOT_CONNECTED`, `CLOSED`, `ALREADY_SENDING`, `RangeError`) are non-terminal by position — they are raised before the wire is entered. The allowlist in `exchange`'s catch (connection.ts:266-270, the SEND_TIMEOUT/INVALID_RESPONSE check) is deleted; a future failure kind is terminal by default. The NAK-exempt check uses `instanceof AckException` today and switches to the `Symbol.for` brand `isAckException` the moment ADR 0019 §7 ships it in @glion/ack (verified not yet present in packages/ack/src) — so terminality survives duplicated package copies.

**Closed-reason chain preserved (no hidden delta).** `fail()` derives the stored `closed.reason` exactly as today: SEND_TIMEOUT and INVALID_RESPONSE are wrapped in the same DROPPED reason text with the trigger on `cause` (matching connection.ts:271-281's `dropConnection` wrapping), so later `CLOSED` errors carry the same cause shape and client.test.ts's cause assertions stay green — a delta the refutation caught in the original spec, closed here by one `toClosedReason()` derivation inside `fail()`.

**Close joins teardown (F15).** The `closed` variant CARRIES `teardown: Promise<void>` — every transition into `closed` stores the real `wire.close()` promise (or resolved), and the `close` command's reply in every phase resolves via it. Joining is the data model; the early-return-without-joining bug (client.ts:366-368) is unrepresentable. `close(): Promise<void>` still never rejects — the duplex contract ("close() MUST resolve") keeps the continuation safe, documented not defended (CLAUDE.md §9).

**Stash ordering (write-first, deliberate).** A stale frame queued between sends is consumed AFTER the next send's write, by the correlation check — never before the write. The alternative (concluding against the stale frame pre-write) can report AA success for a message never written when a duplicate ACK's MSA-2 matches a re-sent MSH-10 — a silent non-delivery hazard in a healthcare library, found in refutation of a rival design and explicitly designed out here. Today's semantics (inbox queue → next take → correlation) are preserved.

**Message hygiene (:291, ADR 0018 §6).** Every message leads with the operation and concrete domain context (host:port, timeout value, both control IDs on a mismatch), never internals; the two invariant apologies are deleted; every user-facing string is asserted verbatim in tests, and a boundary test greps messages for mechanism vocabulary (mailbox, phase, latch, stash) to keep it that way.

**No empty-string defaults (:261).** The `?? ""` at ack.ts:126 (`readValue(tree, "MSA-2[1].1.1") ?? ""`) is deleted; an ACK without MSA-2 is `invalid` → `INVALID_RESPONSE` ("The remote system's acknowledgment carries no MSA-2 control ID, so it cannot be matched to the sent message."); `MllpClientResponse.controlId` is guaranteed non-empty and the README's `controlId: ""` row (README.md:136) is corrected. Calibrated compat note: the baseline tolerated legacy peers that omit MSA-2 (the comment above ack.ts:126 says exactly this); probability a real deployment hits this is low-but-nonzero; the escape hatch is a future explicit compat option, never a silent `""` (flagged for sign-off in Open Questions).

## 7. Adapter contract

Keep the `MllpDuplex`/`MllpConnector` TYPE shapes exactly (they are runtime-agnostic WHATWG surface and were not the complaint); move them to `duplex.ts`; tighten the CONTRACT wording three ways, in the documented-not-defended style (CLAUDE.md §3/§9):

1. **F7 fix — structural, then documentary.** Drop detection moves exclusively to the read pump's done/error branch: the pump posts every `frame` and then `eof` from the same sequential loop, so on a graceful close the final ACK strictly precedes EOF in the mailbox — Web Streams deliver previously enqueued chunks before `done`, so "one-shot peer writes ACK and closes in the same instant" is correct with NO timing requirement (`watchForDrop` and its `setTimeout(resolve, 0)` are deleted, not documented). Scope stated honestly: on an ERROR teardown (ACK then RST) queued-but-unread chunks can be discarded by transform-stream error propagation — identical exposure to today's pipeline, not a regression, and the contract sentence + tests are scoped to clean close. The contract gains the weaker, directly testable clause: "when the connection ends for any reason, `readable` MUST surface end-of-stream or an error to a pending read; bytes the peer wrote before a graceful close MUST be delivered before end-of-stream." A violating custom adapter degrades a drop into a deadline-bounded SEND_TIMEOUT — bounded, never a silently lost ACK (probability ≈0 for Node's `Duplex.toWeb`, low for custom adapters, pinned by the conformance suite). `closed` stays on the interface, no longer in the client's drop path — documented as the observability handle, the stance compatible with issue #686's close-reason direction.
2. **Close-while-locked.** New sentence: "`close()` MUST resolve even while `readable`/`writable` are locked by the client — adapters tear down the underlying transport, not the web streams." Needed because the wire now holds its reader and writer for the connection's lifetime (the Node adapter already complies: its `close()` calls `socket.end()`/`socket.destroy()` directly, runtime/node.ts:96-127).
3. **Connector abort** unchanged: reject on abort-before-resolve, leave nothing live; the just-after-abort orphan is the client's to dispose — now one visible `closed`+`wireOpen` cell instead of an inline aborted-check (client.ts:251-254 today).

Shipped as a reusable conformance suite (a Pipeline graft): `describeMllpDuplexContract(makeDuplex)` in `test/` exercising close-idempotency, either-side `closed`, frames-before-end on graceful close, and close-while-locked — run by node.test.ts today and by every future `/deno`, `/bun`, `/workers` adapter at its own layer. Nothing in actor.ts/wire.ts is Node-specific (setTimeout, web streams, AbortController only); Deno and Bun ship node:net compatibility so `connectNode` likely ports near-verbatim (verify in CI before claiming), and a Workers adapter over `cloudflare:sockets` maps almost field-for-field.

- **D3 (maintainer-directed, :261)**: absent/empty MSA-2 → `INVALID_RESPONSE` (terminal); `controlId` guaranteed non-empty; README row corrected.
- **D4 (behavioral, flagged for sign-off)**: `close()` landing mid-write now uniformly rejects the in-flight send `CLOSED` (today it races to CLOSED or DROPPED depending on which internal microtask the close hit — documented as such in `close()`'s own JSDoc, client.ts:359-363 — exactly the implementation leak §7 of the philosophy bans).
- **Nano-deltas, declared for honesty**: (a) concurrent `connect()` joiners receive equivalent but not identical promise objects (today the `connecting` branch returns the same `#connecting` instance); (b) a frame and a deadline firing in the same instant resolve by mailbox arrival order rather than the inbox's drain-first rule (inbox.ts `take()` drains a queued frame even when the signal already aborted) — divergence window is sub-millisecond and the one-shot-peer pin (connection.test.ts:381 retargeted) still holds because frames precede EOF structurally.

Explicitly NOT added: events, `stream()`, reconnect hooks, caller signal, `sendNoThrow` — no consumer demands them (ADR 0018 §5, CLAUDE.md §12). "Reconnect in / message-retry out" stays future construction-time config; the actor makes it cheap (a `backingOff` phase + a retry counter are new table rows, no runtime change).

## 9. Testing strategy

Five layers; only the adapter suite touches TCP; the matrix layer needs no timers at all.

1. **codec.test.ts** (pure): today's ack.test.ts (489 LOC) + outbound cases retarget onto `encode`/`decode` asserting `AckOutcome` variants; new pins: missing-MSA-2 → invalid, ERR-8 text fallback, exotic-parser-throw → invalid (the never-throw contract, tested against non-Error throws), verbatim message-string assertions (ADR 0018 §6).
2. **actor.test.ts** (the centerpiece; no streams, no sockets, no fake timers): a stub `Wire` (`{write: spy, close: () => teardownDeferred.promise}`) and stub codec; deadlines are POSTED as messages (Loom graft), so every test is synchronous. The suite enumerates the full [4 phase x 10 message] matrix — every cell including every straggler no-op gets a named test — plus adversarial permutations ([send, frame, sendDeadline] vs [send, sendDeadline, frame]; [close, wireOpen]; [close, close, teardown-settles]; [send, eof]; flood at frame 17), asserting the full `(state, settlements, effects-started)` triple as data (Loom graft). Harness invariants after every sequence: all reply Deferreds settled; `closed` ⇒ no live timers. Test names mined from #667's legality-table matrix and the baseline §3/§4 checklists so coverage is traceable row-per-test.
3. **wire.test.ts** (fake duplex, streams, no sockets): frames post in order; EOF posts strictly after buffered frames on graceful close (the F7 pin); write failure posts `writeFailed`; Node-20 sync-throw absorbed; close idempotent.
4. **client.test.ts** (kept, 1,146 LOC): the public-behavior regression net over fake-duplex, edited only for the declared deltas (D1-D4 + nano-deltas); the release-before-resolve test (`await send(); send()`, baseline §3.2) and the one-shot-peer drain-first pin land FIRST, before the cutover commit; a small fake-timer suite verifies timer wiring (`vi.getTimerCount()` returns 0 after a resolved send — the leak pin). Shared helpers consolidated into `test/helpers` (kills the flagged duplication).
5. **node.test.ts** (kept, 307 LOC) + the extracted `describeMllpDuplexContract` suite + an unref assertion on the grace timer.

Coverage ≥ 94.20% is credible with margin: the branches that dragged #669 under target (detached catches, unreachable invariant fallbacks, the exhaustiveness default arms) are exactly the code this design deletes, and matrix enumeration takes actor.ts to effectively full branch coverage; the F1 validation tests land on #669 pre-merge and start closing the gap immediately.

## 11. Calibrated risks

(1) The maintainer may read the mailbox as over-built for one socket (§1) — the arithmetic: ~85 net-new lines of machinery delete inbox.ts (161), watchForDrop, the abortReason routing, and the dual detached catches, net −270 LOC, and one concept replaces four ad-hoc ones; if the pattern is rejected the design does not degrade gracefully into the current shape. (2) The handlers-never-await/never-throw invariants are enforced by signature + codec totality + review, not fully by the compiler; mitigated by the header comment, `void` return types, total-codec tests, and matrix tests that catch most resulting reorderings. (3) D3 (MSA-2 throws) can break a real legacy peer — low-but-nonzero; sign-off required; compat option named, deliberately unbuilt. (4) F7's graceful-close scoping means an adapter whose `readable` parks forever after teardown converts a drop into a deadline-bounded SEND_TIMEOUT — degraded diagnostics, never corruption; conformance suite protects adapters that run it. (5) Stack traces for `send()` rejections originate in handlers, one hop less direct than today — cosmetic, stated up front. (6) ERR-2→`location` stays blocked on @glion/ack shipping `location` (ADR 0019 PR sequence — the §7 sketch is spec, not code); no doc may claim the glion→glion round trip is closed until then.
